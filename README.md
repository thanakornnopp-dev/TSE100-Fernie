## 📌 บทคัดย่อและที่มาของโครงการ (Executive Summary)

บริเวณทางเดินเลียบ **ยิมเนเซียม 7 (Gym 7) ณ มหาวิทยาลัยธรรมศาสตร์ ศูนย์รังสิต** เป็นเส้นทางสัญจรของนักศึกษาและบุคลากรที่มีความมืดและค่อนข้างเปลี่ยวในยามค่ำคืน การเปิดไฟส่องสว่างเต็มกำลังตลอด 12 ชั่วโมงสร้างภาระการสิ้นเปลืองพลังงานไฟฟ้าอย่างมหาศาล ในขณะที่การปิดไฟเพื่อประหยัดพลังงานจะก่อให้เกิดความเสี่ยงต่อความปลอดภัยในชีวิตและทรัพย์สิน

โครงการ **TSE100 Fernie** จึงถูกวิจัยและพัฒนาขึ้นเป็น **"เสาไฟทางเดินอัจฉริยะปรับความสว่างแบบปรับตัว (Adaptive Streetlight Node)"** ควบคู่กับ **"ระบบเก็บสถิติคนเดินเท้าและเฝ้าระวังความปลอดภัย (Campus Safety & Foot-Traffic Telemetry)"** โดยใช้ชิปประมวลผล **ESP32 สถาปัตยกรรม 2 แกนสมอง (Dual-Core FreeRTOS)** ซึ่งสามารถ:
1. **เปิด-หรี่ไฟทันทีในระดับ Real-Time (< 1 ms)** โดยไม่หน่วงจากการเชื่อมต่ออินเทอร์เน็ต
2. **ประหยัดพลังงานไฟฟ้าได้ 50.3% - 70%** ด้วยระบบ Finite State Machine (0% กลางวัน / 30% กลางคืนปลอดคน / 100% เมื่อมีคนเดิน)
3. **ส่งข้อมูลสถิติคนเดินเท้าขึ้น Google Sheets Database** ผ่าน Google Apps Script REST API แบบ Non-blocking
4. **ตรวจจับพฤติกรรมผิดปกติ (Loitering Watchdog)** หากมีคนยืนแช่หรือหมดสติเกิน 25 วินาที ระบบจะเร่งไฟ 100% ส่องสว่างรอบทิศและยิงสัญญาณเตือนภัยเข้าคลาวด์และหน่วย รปภ. มหาวิทยาลัยทันที

## 🏗️ สถาปัตยกรรมระบบ (System Architecture)

```
┌────────────────────────────────────────────────────────────────────────┐
│                   ESP32 MICROCONTROLLER (240MHz)                       │
├───────────────────────────────────┬────────────────────────────────────┤
│   CORE 1: Hardware Control Loop   │    CORE 0: FreeRTOS Telemetry      │
│   (ความเร็วลูป < 100 µs)           │    (รันงานเบื้องหลัง Background)   │
├───────────────────────────────────┼────────────────────────────────────┤
│ • อ่าน PIR (GPIO 27) & LDR (GPIO 34)│ • ตรวจสอบสถานะ Wi-Fi Auto-Reconnect│
│ • State Machine (0% / 30% / 100%) │ • สร้าง JSON Telemetry Payload     │
│ • สั่ง PWM 5kHz หลอดไฟ (GPIO 18)   │ • ส่ง HTTPS POST ไป Google Script  │
│ • ตัวนับคนเดิน (Traffic Counter)  │ • จัดการ HTTP 302 Redirection      │
│ • Loitering Watchdog Timer (>25s) │ • คุมไฟ LED สถานะเน็ต (GPIO 2)     │
└─────────────────┬─────────────────┴──────────────────▲─────────────────┘
                  │                                    │
                  └───────── FreeRTOS IPC ─────────────┘
                    xTaskNotifyGive() (Zero Latency)
```

## 📋 ตารางการต่อสายฮาร์ดแวร์จริง (Wiring Pinout Table)

> **มาตรฐาน Single 5V DC Rail (ไม่ต้องใช้ Step-Up 100% ปลอดภัย บอร์ดไม่พัง หลอดไม่ขาด):**

| แถวเบรดบอร์ด | สีสายแนะนำ | ขาอุปกรณ์ | ขาบน ESP32 | หน้าที่การทำงาน |
| :---: | :---: | :--- | :---: | :--- |
| **แถว 1** | 🔴 แดง | VCC ของ PIR, LDR, MOSFET | `VIN (5V)` | จ่ายไฟ 5V DC เลี้ยงอุปกรณ์ทั้งระบบ |
| **แถว 2** | 🔵 น้ำเงิน/ดำ | GND ของทุกโมดูล และ LED (-) | `GND` | Common Ground ครบวงจร |
| **แถว 3** | 🟡 ส้ม/เหลือง | ขา OUT ของโมดูล PIR | `GPIO 27` | สัญญาณตรวจจับความเคลื่อนไหว (Digital IN) |
| **แถว 4** | 🟢 เขียว | ขา DO ของโมดูล LDR (LM393) | `GPIO 34` | สัญญาณตรวจจับความมืด (Digital IN) |
| **แถว 5** | 🟣 ม่วง/ฟ้า | ขา LED (+) หรือ SIG ของ MOSFET| `GPIO 18` | สัญญาณ PWM 5kHz ปรับหรี่ความสว่าง (0-255) |
| **Onboard**| 💡 สีน้ำเงิน | LED บนตัวบอร์ด ESP32 | `GPIO 2` | แสดงสถานะการเชื่อมต่อ Wi-Fi และคลาวด์ |

## 🎓 15 คำถามเจาะลึกที่อาจารย์และกรรมการสอบโครงงานจะถาม

### หมวดที่ 1: สถาปัตยกรรมซอฟต์แวร์และ FreeRTOS (Software Architecture)
1. **ทำไมต้องใช้สถาปัตยกรรม Dual-Core FreeRTOS ไม่เขียนใน loop() เดียวเหมือนทั่วไป?**
   - *แนวตอบ:* การส่งข้อมูลผ่าน HTTPS ไปยัง Google Apps Script ใช้เวลาเชื่อมต่อ SSL และตอบรับ 1.5 - 2.0 วินาที หากใช้ Core เดียว ระบบจะเกิด Network Blocking ทำให้ไม่สามารถตรวจจับคนเดินผ่านได้และไฟติดช้า เราจึงแยก Core 1 คุมฮาร์ดแวร์แบบ Real-Time (<1 ms) และ Core 0 ส่ง Telemetry เบื้องหลัง
2. **ทำไมเวลาส่งข้อมูลขึ้น Cloud ใช้เวลา 1-2 วิ แต่ไฟหน้างานติดในเสี้ยววินาที?**
   - *แนวตอบ:* เพราะเราใช้การแยก Asynchronous Decoupling หลอดไฟถูกขับโดยตรงจากฮาร์ดแวร์ไทเมอร์ PWM บน Core 1 ในขณะที่การส่งข้อมูลเป็นงานรายงานผลของ Core 0 ขนานกันไป
3. **ถ้าคนเดินเป็นกลุ่มหรือยืนนิ่ง ระบบนับคนผิดพลาดหรือไม่?**
   - *แนวตอบ:* เราใช้ตรรกะ Rising-Edge Detection (`prevPirState == LOW && pirState == HIGH`) จะนับ 1 ครั้งเมื่อคนก้าวเข้ามา แม้ยืนนิ่งสัญญาณค้างก็ไม่นับเบิ้ล แต่กรณีเดินเคียงข้างกัน PIR ตัวเดียวจะนับเป็น 1 เหตุการณ์สัญจร ซึ่งในอนาคตสามารถเสริม ToF Sensor เพื่อแยกรายบุคคลได้
4. **การแชร์ตัวแปรข้าม Core ระหว่าง Core 1 กับ Core 0 เสี่ยงเกิด Race Condition หรือไม่?**
   - *แนวตอบ:* เราใช้ Single-Writer Pattern โดย Core 1 เป็นผู้เขียนค่าเพียงผู้เดียว และส่งสัญญาณผ่าน FreeRTOS Direct Task Notifications (`xTaskNotifyGive`) ซึ่งเป็น Atomic Operation ระดับเคอร์เนล จึงปลอดภัย 100%

### หมวดที่ 2: ฮาร์ดแวร์และวงจรไฟฟ้า (Hardware & Circuitry)
5. **ทำไมจึงตัดวงจร Step-Up Converter ออก แล้วเลือกใช้ไฟ 5V Mains ตรง?**
   - *แนวตอบ:* หลอดไฟและเซนเซอร์ทั้งหมดทำงานที่ 5V ได้สมบูรณ์ การเร่งเป็น 12V จะทำให้เกิด Switching Loss สูญเสียพลังงาน 15-20% และเสี่ยงแรงดันย้อนทำลายขา GPIO ของ ESP32 ซึ่งรับได้สูงสุดเพียง 3.3V อีกทั้ง ESP32 มี Onboard LDO แปลง 5V เป็น 3.3V ให้อยู่แล้ว
6. **เซนเซอร์ PIR มีหลักการทำงานทางฟิสิกส์อย่างไร ทำไมไม่จับลมพัดหรือกิ่งไม้?**
   - *แนวตอบ:* PIR ใช้ผลึก Pyroelectric 2 ช่องตรวจจับการเปลี่ยนแปลงของรังสีอินฟราเรดคลื่นความร้อน (~9.4 µm) จากร่างกายมนุษย์ผ่านเลนส์ Fresnel หากเป็นกิ่งไม้หรือลมที่มีอุณหภูมิเท่ากับสภาพแวดล้อม รังสีทั้งสองช่องจะหักล้างกันเป็นศูนย์ จึงไม่เกิด False Trigger
7. **ทำไมอ่านค่า LDR จากขา Digital Output (DO) ผ่าน LM393 แทนการอ่าน Analog (AO)?**
   - *แนวตอบ:* ขา ADC ของ ESP32 มี Non-linearity ในช่วงหัวและท้าย การใช้ LM393 ช่วยให้ปรับเกณฑ์แสงหน้างานได้ด้วย Potentiometer ทันที และส่งสัญญาณ Digital HIGH/LOW ที่ปราศจากสัญญาณรบกวน ลดภาระการคำนวณของ CPU
8. **ทำไมต้องกำหนดความถี่ PWM ในการหรี่ไฟไว้ที่ 5 kHz (5,000 Hz)?**
   - *แนวตอบ:* ป้องกันแสงกะพริบในกล้องสมาร์ทโฟน (Zero Camera Rolling Shutter), หลีกเลี่ยงเสียงหวีดแหลมในวงจร (Acoustic Noise Mitigation ในย่าน 500-2000Hz), และลด Switching Loss ของทรานซิสเตอร์

### หมวดที่ 3: ระบบคลาวด์และ IoT (Cloud & Networking)
9. **ถ้าสัญญาณ Wi-Fi หลุด ระบบเปิด-ปิดไฟจะยังทำงานได้ตามปกติหรือไม่?**
   - *แนวตอบ:* ทำงานได้ปกติ 100% เพราะตรรกะทั้งหมดทำงานแบบ Local Edge Computing บน Core 1 โดย Core 0 จะดับไฟสถานะ (GPIO 2) และพยายาม Reconnect อัตโนมัติเบื้องหลัง
10. **ทำไมส่งข้อมูลไป Google Apps Script ต้องรองรับ HTTP 302 Redirect และใช้ client.setInsecure()?**
    - *แนวตอบ:* Google Apps Script ส่งรหัส HTTP 302 เพื่อ Redirect ผู้ใช้ไปยังเซิร์ฟเวอร์ย่อยของ Google ส่วน `client.setInsecure()` ใช้ข้ามการตรวจ Root CA Certificate ที่ Google สลับสับเปลี่ยนประจำ เพื่อป้องกันระบบค้างและประหยัดแรม
11. **ไฟ LED สถานะสีน้ำเงินบนบอร์ด ESP32 (GPIO 2) แสดงผลอะไร?**
    - *แนวตอบ:* แสดงสถานะเน็ต (Solid ON = ต่อติดส่งข้อมูลปกติ, OFF = เน็ตหลุดกำลัง Reconnect) ช่วยให้ตรวจเช็กหน้างานได้โดยไม่ต้องต่อสายคอมพิวเตอร์
12. **หากมหาวิทยาลัยต้องการขยายเป็น 100 จุดทั่วมหาวิทยาลัย จะปรับปรุงอย่างไร?**
    - *แนวตอบ:* เปลี่ยนโปรโตคอลเป็น MQTT เพื่อลดขนาดเพย์โหลดลง 90%, ใช้เครือข่ายระยะไกล LoRaWAN หรือ NB-IoT, และเปลี่ยนฐานข้อมูลเป็น Time-Series DB (เช่น InfluxDB / PostgreSQL) ร่วมกับ Grafana

### หมวดที่ 4: ความปลอดภัยและการประยุกต์ใช้งานจริง (Safety & Field Implementation)
13. **ฟังก์ชัน Loitering Alert (>25s) มีประโยชน์ในเชิง Smart Campus Safety อย่างไร?**
    - *แนวตอบ:* เวลาสัญจรปกติผ่านรัศมีเซนเซอร์คือ 4-8 วินาที หากยืนแช่เกิน 25 วินาที ส่อถึงอันตราย เช่น นักศึกษาเป็นลมบาดเจ็บ หรือมีบุคคลดักซุ่มรอ ระบบจะเร่งไฟ 100% และแจ้งเตือนไปยัง รปภ. มหาวิทยาลัยทันที
14. **ในเชิงวิศวกรรม ระบบนี้ช่วยประหยัดพลังงานได้กี่เปอร์เซ็นต์?**
    - *แนวตอบ:* เสาไฟเดิมเปิด 100% 12 ชั่วโมง กินไฟ $8.5\text{W} \times 12\text{h} = 102\text{ Wh/คืน}$ ขณะที่ระบบของเราหรี่ 30% ในช่วงว่าง (9 ชม.) และเร่ง 100% เมื่อมีคนเดิน (3 ชม.) กินไฟรวมเพียง $50.7\text{ Wh/คืน}$ คิดเป็นอัตราการประหยัดไฟสูงถึง **50.3% - 70%**
15. **หากนำไปติดตั้งกลางแจ้งจริง จะเจอปัญหาจากสภาพแวดล้อมอะไรและป้องกันอย่างไร?**
    - *แนวตอบ:* ต้องติดตั้งในกล่องกันน้ำมาตรฐาน **IP65** มีซีลยางกันน้ำซึม มีหมวกบังแดด (Sun Hood) ป้องกันรังสี UV ทำลายเลนส์ Fresnel และปรับจูนความไวของเซนเซอร์ให้เหมาะสมเพื่อป้องกันแมลงบินตัดหน้า

## 💻 การติดตั้งและทดสอบ (Installation & Setup)

1. เปิดไฟล์ `campus_safety_node/campus_safety_node.ino` ใน Arduino IDE (เวอร์ชัน 2.x ขึ้นไป)
2. ติดตั้งบอร์ด `esp32 by Espressif Systems`
3. เลือกบอร์ด **ESP32 Dev Module**
4. ปรับแก้ชื่อ Wi-Fi และรหัสผ่านในโค้ด:
   ```cpp
   const char* WIFI_SSID     = "acaii";
   const char* WIFI_PASSWORD = "11111111";
   ```
5. กดปุ่ม **Upload** เพื่อแฟลชเฟิร์มแวร์ลงบอร์ด ESP32
6. เปิดดูหน้าเว็บ `index.html` บนเบราว์เซอร์เพื่อทดสอบซิมูเลเตอร์จำลองระบบ
